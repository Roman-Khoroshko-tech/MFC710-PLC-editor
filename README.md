# MFC710 PLC Studio

Візуальний редактор логіки вбудованого PLC перетворювача MFC710. Схема перетворюється на таблицю параметрів для ручного введення у ПЧ.

**Статус: передрелізна версія 0.1.0-rc.1.** Це інженерний редактор, без симуляції та підключення до фізичного ПЧ.

## Використання

Відкрийте сайт GitHub Pages або файл `MFC710_PLC_Studio.html` у браузері. Сервер, обліковий запис і встановлення бібліотек для редактора не потрібні.

- 49 функцій: 0–43 і 45–49; до 48 функціональних блоків та 24 програмованих сталих.
- З’єднання портів в обох напрямках, пари посилань, точки маршруту ліній, текстові коментарі.
- Рамка виділення, групове переміщення, Delete, Ctrl+Z, Ctrl+Shift+Z.
- Масштаб Ctrl+колесо, переміщення затиснутим колесом, центрування схеми.
- Інтерфейс UA / EN / PL; вибрана мова зберігається в браузері.
- Збереження й завантаження JSON, таблиця параметрів, CSV, друк/PDF.
- 10 практичних прикладів.

Автозбереження зберігається локально у браузері. Проєкти не відправляються редактором на сервер. Історія скасування діє в поточному сеансі сторінки. Для резервної копії натискайте **Зберегти**. Перехід з локального HTML на сайт або на інший домен не переносить автозбереження: збережіть JSON у старій версії та завантажте його в новій.

Покрокова інструкція: [PUBLISH_GITHUB.md](PUBLISH_GITHUB.md).

Для GitHub Pages використовуйте гілку **main**, папку **/docs**. У ній уже є готовий `index.html` і `.nojekyll`. Репозиторій містить вихідний код і перевірки; в GitHub Pages публікується тільки вміст `docs`.

## Розробка і перевірки

Рекомендоване середовище перевірки: Node.js 24. Для основних команд немає залежностей npm і не потрібен `npm install`.

```sh
npm test
npm run build
npm run check:pages
npm run test:report
npm start
```

Локальний сервер відкривається за адресою http://127.0.0.1:7310. Змінюйте код у `dist/`, потім запускайте перевірки та збирання. Не редагуйте вручну згенеровані `docs/index.html` і `MFC710_PLC_Studio.html`.

GitHub Actions запускає основні перевірки при push і pull request та перевіряє відповідність готової сторінки вихідному коду. Для цього workflow не потрібні токени користувача чи окремі секрети. CI перевіряє код; публікація Pages з гілки є окремим процесом і не очікує результату цього CI.

Додатковий `npm run test:browser` потребує Playwright та встановленого браузера; він не входить до звичайного CI. Фактичний стан браузерної перевірки наведено у [QA_REPORT.md](QA_REPORT.md).

## Технічна основа та обмеження

Базова логіка: надана українська інструкція MFC710 редакції 7.4. Англійська та польська термінологія і довідкові сторінки: надані інструкції MFC710 з панеллю OP-11, редакція 8.1. Текстові витяги містяться в `dist/references/`; ілюстрації не включено. Вибір мови не змінює параметри або сумісність прошивки.

Додаток B описує функції до 49, а додаток C обмежує групу 6 діапазоном 0–39. Експорт старших функцій потребує окремого підтвердження користувачем підтримки на конкретному ПЧ. Числові межі звичайних входів не всюди визначені; робоча межа редактора ±32000 не є універсальною специфікацією ПЧ.

Слоти ущільнюються до 1…N з перенесенням PCH-зв’язків; 5.145 визначається автоматично. Експорт включає тільки задіяні блоки. Для призначень ПЧ перед повними покажчиками додається введення коду у 4.2, потім 4.6 = 1. Для порожньої схеми PLC залишається вимкненим. Введення конфігурації потребує перевірки та зупиненого ПЧ.

Повна конфігурація двигуна, PID, фізичних входів/виходів та мережевого обміну не входить у редактор. Автоматизовані перевірки не підтверджують роботу на конкретній прошивці ПЧ. Візуальне приймання в цільових браузерах і перевірка на MFC710 залишаються окремими етапами.
